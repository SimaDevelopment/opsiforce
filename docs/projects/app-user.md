# App User

> How do visitors sign in to an App with accounts the owner keeps in Opsiforce, and how does the owner manage those accounts?

## How it works

### Accounts

- Each [App User](../../GLOSSARY.md) belongs to one [Project](../../GLOSSARY.md) and is shared by every [ProjectEnvironment](../../GLOSSARY.md) whose [Auth mode](../../GLOSSARY.md) is `app_users` ([ADR-0099](../adr/0099-app-users-sign-in-through-an-oidc-provider-the-backend-runs-with-one-client-per-projectenvironment.md)).
- The owner manages them on the project's Users tab, a full page next to Chat, Files, Code and DB that hides the App preview: a table with search, role and status filters, bulk enable, disable and delete, and a strip naming the environments that use App Users, each opening its App Auth. App Auth itself only chooses the mode and links to the tab.
- An owner invites a user by email, with an optional name and any roles. By default the account has no password and a one-time invite link (7 days) lets the person choose their own: Opsiforce emails it when Mailgun is set up (the owner can untick that), and the owner can always copy it; the owner may instead set a password of 8 to 256 characters, generated by default, and copy the sign-in details. An account without a password shows as Invited and cannot sign in.
- Editing changes email, name and roles. For a password the owner emails or copies a one-time reset link (24 hours), or sets a new password directly; both sign the user out everywhere and lift a lock. A new link replaces the user's previous link of that kind, so Email Again on a shown link sends a fresh one and the old one stops working.
- Emails are stored lower-cased and are unique within the Project; the same email may hold an account in another Project.
- Gated by `can_manage_project_auth_settings` ([Permissions](../organization/permissions.md)).

### Roles

- A Project defines its own roles on the Users tab's Roles view: a name of 1 to 40 lowercase letters, digits, `-` or `_`, an optional description, and how many users hold it. A Project has at most 50.
- A user holds any number of roles. Renaming a role renames it for every holder; deleting it takes it from them and keeps their accounts.
- The Roles view shows the headers the App receives, so the owner and the App's code agree on the names.

### Resetting a password

- Emails go through the platform's Mailgun account (`MAILGUN_API_KEY`, `MAILGUN_DOMAIN`, `MAILGUN_SENDER` and, locally, `MAILGUN_URL` pointing at the mock), the same one Makara uses. Without it nothing is emailed and the owner copies every link.
- With Mailgun the sign-in page links to "Forgot password?": the visitor enters their email and receives a reset link that works for 1 hour and returns them to the sign-in they started. The answer never says whether the email has an account, a failed send looks the same to the visitor, and an account gets at most one email a minute.
- Without Mailgun the sign-in page tells a visitor to ask the App's owner for a reset link.
- When Mailgun refuses an owner's email, the link still exists: the Users tab says the email failed and shows the link to copy.
- A link's page asks for the new password twice. A used, replaced or expired link, or one for a disabled account, shows that the link has expired.

### Signing in

- Choosing App Users points the environment's App Auth Middleware at the backend's own OIDC provider, with the environment id as its client ([Environments](environments.md)).
- A visitor without a session is sent to the provider's sign-in page on the Opsiforce origin, titled with the App's name, and comes back signed in to the App's URL.
- A provider session per Project, kept for 7 days in a cookie on `/api/app-auth`, signs the visitor straight back in after the App's own session ends.
- The App receives the visitor in `X-Oidc-Subject` (the App User's id), `X-Oidc-Email`, `X-Oidc-Name` and `X-Oidc-Roles`, a JSON array of role names such as `["admin","editor"]` (`[]` without roles). A visitor signs out at the App's `/oidc/logout`, which also ends the provider session.
- ID tokens last 5 minutes and the gate renews them with a refresh token, which re-reads the account on every renewal.

## Edge cases

- When an App User is disabled, deleted or given a new password, their open sessions end at the next renewal, within 5 minutes. A change to their email, name or roles reaches the App at that renewal too.
- When a disabled App User enters the right password, the sign-in page says the account is disabled; a wrong password never reveals that.
- When five wrong passwords are entered in a row, the account refuses sign-in for 15 minutes; the owner's list shows it as Locked until then, and a password reset unlocks it.
- When a sign-in link names a callback URL on a host the environment's gate does not serve, or an environment not in `app_users`, the provider shows an error page and redirects nowhere. Any host the gate serves is accepted, such as an App's address from before an Edit URL, and so is every [Custom domain](../../GLOSSARY.md) that serves the App on its own host; one set to redirect to the Main domain is not, since visitors never sign in there.
- When a Project is duplicated, the copy keeps `app_users` but none of the accounts, so no one can sign in to it until the owner adds App Users ([Duplication](duplication.md)).
- When the sign-in form is submitted without its anti-forgery cookie, it is refused and the visitor starts again from the App.
- When `OIDC_PLUGIN_SECRET` or `OPSIFORCE_PUBLIC_URL` is unset, the backend refuses the `app_users` mode.

## Code

- `backend/src/app-users/` — accounts, roles, one-time links and their emails, the OIDC provider routes, the sign-in, forgot-password and set-password pages and the sealed signing key.
- `backend/src/project/project-app-users.controller.ts` — the owner's API for accounts, roles and links.
- `backend/src/project/project-auth.service.ts` — the Middleware that `app_users` applies.
- `app_users` in `backend/db/schema.ts` — the accounts, with `app_user_roles`, `app_user_role_members`, `app_user_links`, `app_user_authorization_codes` and `app_user_signing_keys`.
- `frontend/src/components/project/users/` — the Users tab.
- `frontend/src/components/project-auth/` — the App Users mode in the App Auth dialog.
- `helm/opsiforce-proxy/` — the edge that lets the provider through without the platform's sign-in.
