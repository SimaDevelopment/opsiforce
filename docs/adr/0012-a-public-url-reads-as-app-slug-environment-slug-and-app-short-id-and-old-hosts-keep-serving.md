# A Public URL reads as App Slug, Environment Slug and App Short ID, and old hosts keep serving

An environment uuid in a host, even with `-dev` after it, gives no hint which App a link opens, and a client holding a dozen such links cannot tell them apart. **An App's Public URL is `{App Slug}-{Environment Slug}-{App Short ID}.apps…`**, e.g. `equipment-monitor-dev-6713b7a51450.apps.dev.opsima.com` for the environment `6713b7a5-1450-45f0-8fd0-321f11bf22e2`, and only the App Short ID decides which App answers. The App Slug changes only through Edit URL, and every host ever handed out keeps reaching its App, because links already sit in chats, bookmarks, CI configuration and identity providers' callback lists: legacy hosts serve, and a readable host with an outdated App Slug redirects.

**Environment Slug.** It is an immutable, DNS-safe column on the tenant Environment registry: `dev` and `prod` for the protected Environments. For a custom one the create dialog prefills it from the whole name (lowercased, diacritics stripped, non-alphanumeric runs collapsed to dashes, capped at 26 characters), and the admin may edit it that one time before saving: `[a-z0-9-]`, no dash at either end, unique per tenant, which also blocks `dev` and `prod`. Renames never touch it, and a name with no latin letters or digits prefills nothing, so the admin types the slug.

**App Short ID.**

- It is the first twelve hex characters of the ProjectEnvironment's id with dashes dropped, stored in `project_environments.short_id` and unique across every tenant. When that prefix is taken it extends by two hex characters at a time. Twelve hex characters (48 bits) keep collisions rare at any number of environments the platform will hold and make scanning the apps domain for live Apps impractical, for four more characters in every label. No id is regenerated, because Development's id is the Project's id ([ADR-0002](0002-development-environment-reuses-project-id.md)).
- A database trigger assigns it on insert through a SQL function, the codebase's only trigger. Every writer of `project_environments` (project create, import, duplicate, publish, warm pool) gets it inside its own transaction without knowing about it, and an advisory lock on the twelve-character prefix keeps two concurrent inserts from taking the same id.

**The backend reads the host.** The Go proxy sends the full host, unparsed, to the backend's App ensure call and does what it answers: serve, redirect to `canonicalHost`, or 404. Only the backend can map an App Short ID to an environment and its current App Slug, and a later custom domain is one more host the same call looks up, with no new parsing in Go. The backend fails closed: only one label of `[a-z0-9-]`, no dash at either end, at most 63 characters, directly under the apps domain and with no trailing dot resolves, because a host App Auth's patterns don't match reaches the proxy through the unauthenticated catch-all, and Traefik's `HostRegexp` sees the trailing dot that `Host()` forgives. The label resolves in order:

1. A label that is a full 36-character environment uuid, alone or followed by a dash, takes the legacy path when that environment exists. The bare uuid, or the uuid followed by its own Environment Slug, serves; any other suffix redirects to that environment's canonical host.
2. Otherwise, a missed uuid included, the hex text after the label's last dash is the App Short ID when it is at least twelve characters long. Ids are hex and never contain a dash, so the rule holds at any length. The label serves when it equals the canonical label; any other label ending in the id (an outdated or mistyped App Slug) answers with a 308 to the canonical host, without waking the App's pod. The 308 carries `Cache-Control: no-store`, since a browser keeps an unmarked 308 forever and an Edit URL back to an earlier App Slug would then loop.

A warm-pool row still pending or claiming answers 404 on every host, since its id becomes a Project's id and a redirect would reveal it. The in-product preview frames `{envId}` on the deployment's preview apps domain, the platform's own view of the App outside App Auth; it serves by id and never redirects.

**Hosts that serve.** The canonical host is the readable one once the App has an App Slug, and otherwise the legacy `{envId}-{Environment Slug}` host, or the bare `{envId}` host for a warm-pool row with no Environment yet. Both legacy hosts serve forever with no redirect: the CI Bifrost provider and registered OIDC callbacks use them, and some API clients drop the body or auth headers on a cross-host redirect.

**App Slug.**

- It is derived with `slugify` (simov): transliterated, every other character run collapsed to one dash, cut with no trailing dash to 63 − (Environment Slug + 1) − (App Short ID + 1) characters so the label fits DNS, and `app` when nothing readable is left or the result starts with a uuid, which would take the legacy path. The Environment Slug prefill and Custom Agent bundle slugs keep their own slug functions.
- It is set when the go-live report first creates the App's row: from the App's name, or for a published environment from Development's App Slug. A Duplicate's Development and an imported App start from the source's App Slug or the one the export carries. Every copy falls back to its own name when its source has none and is cut again to fit its own label, since a longer Environment Slug or App Short ID leaves less room. An App whose environment's sign-in callbacks are registered with an identity provider outside the platform (manual App Auth), a Duplicate of one included, gets none: that owner registered the legacy host's callback, so the App keeps it.
- Only Edit URL changes it, gated by `can_edit_app_details` and open once the App has gone live. The slug is taken as typed: `[a-z0-9-]`, no dash at either end, no dashes as the 3rd and 4th characters (reserved for punycode, so `xn--…` can't render as look-alike Unicode), within the length budget, and not starting with a uuid, since such a label takes the legacy path. It need not be unique, because the App Short ID already is. Renaming the App leaves it alone.

**Existing Apps switch at the upgrade.** At every start the backend gives each App without an App Slug one derived from its current name, so an App that went live before App Slugs takes its readable address at the first start after the upgrade. Two kinds keep their legacy host: an App with manual App Auth, whose owner registered the legacy host's callback, and a Project that serves an External Service, which has no Public URL. The environment list offers an App Slug derived from the current name for every App left without one except an External Service's, the Edit URL dialog starts from it, and the App pane shows the readable address it gives with a Switch action; Edit URL warns a manual App Auth owner to register the new host's sign-in callback first.

**App Auth matches by pattern.** The per-environment auth IngressRoute ([ADR-0007](0007-per-environment-app-auth.md)) has two rules above the catch-all apps route: a `HostRegexp` on any label ending in `-{App Short ID}` at priority 100, and a `HostRegexp` on the environment id alone or followed by a dash and any suffix at priority 101, which covers both legacy hosts and every `{envId}-…` label the backend redirects. Every host the backend serves or redirects matches one of them. A new Environment Slug cannot end with 12 or more characters from 0-9 and a-f, so `{envId}-{slug}` never ends like another App's Short ID and a public environment's legacy host, which has no route of its own, never runs another App's sign-in; for a slug created before that rule the environment-id rule outranks every App Short ID pattern. An App Slug change never writes to Kubernetes, and an outdated-slug host asks for sign-in before its 308. At every start, and once more five minutes later, the backend rewrites any route whose rules differ from the ones its environment should have and never touches the OIDC Middleware, so a change to the rules reaches routes written before it, including those an outgoing replica writes after the new one starts. The middleware's callback is the relative `/oidc/callback`, so each host completes its own sign-in and carries its own host-scoped session cookie.

**A protected App never answers through the catch-all.** Route drift, whether a missing, stale or mis-written gate route or a future bug, would otherwise hand a protected App's host to the catch-all apps route, which signs no one in. That route alone carries a static Traefik `headers` Middleware that sets `X-Opsiforce-Unprotected-Route: 1`, overwriting any value a client sent. The backend's App ensure answer carries `protected`, true when the environment's App Auth mode is not `public`, and the app proxy answers a marked request for a protected App with a 403, for a redirect as for a serve, so the catch-all never names the App. It never contacts the pod, logs a warning naming the environment, since drift is the operator's to fix, and strips the marker with every other reserved `X-Opsiforce-*` header before App code could see it.

**The agent learns its link from the platform.** `APP_PUBLIC_URL` is fixed at pod start to the canonical host of that moment, so a warm-pool pod, started before its Project exists, gets the bare `{envId}` host. The link the agent shares in chat comes from `app-url`, which asks the gateway for the current Public URL once go-live is recorded, so it is right after an Edit URL too.

**Scope.** The public apps host only. The preview, VS Code and DB hosts keep their bare env-id labels.

## Considered options

- **App Slug follows every rename, with outdated slugs 308ing** (Stack Overflow style): the URL never disagrees with the name, but a rename silently moves the host. That breaks manual App Auth sign-in until the owner registers a new callback, and the owner never chose to move anything.
- **Base44's model, where a rename or Edit URL moves the URL and the old link stops working:** a shared link must outlive a rename.
- **Id-less vanity hosts (`warehouse.apps…`):** these need a name unique across every tenant and a lookup by name, and they invite squatting. Readable id-less addresses belong to a custom-domain feature.
- **One id per Project, with the Environment Slug choosing the environment** (`{projectId}-{slug}`, or one App Short ID per Project): a stable base per Project, but it changes the routing key of published environments, makes the Environment Slug routing data, and a dashed slug such as `staging-eu` makes the label ambiguous to parse.
- **App Short ID first (`6713b7a51450-equipment-monitor-dev`):** easy to parse, but the readable part is no longer what the eye lands on.
- **Environment Slug derived from the live registry name:** no schema change, but renaming a custom Environment would move every bound App's address at once, breaking bookmarks and registered callbacks.
- **Assigning the App Short ID in application code:** every insert path would have to remember it and run the collision check inside its own transaction.
- **`@sindresorhus/slugify` or `any-ascii` for the App Slug:** the first gives щ→sch and is ESM-only with two dependencies; the second gives Ї→i and weighs 553 KB. `slugify` has no dependencies and romanizes Ukrainian correctly.
- **A per-environment signed route proof** (each gate route adds a `headers` Middleware carrying an HMAC of its environment id, which the app proxy checks): it would also cover routes outside the catch-all, but it adds a Middleware per environment to every App Auth write and to the start-up rewrite, makes the token-forwarding signing key mandatory everywhere, and needs two releases or every protected App answers 404 until its route is rewritten. A custom domain, the first route outside the catch-all, is where it earns that cost.
- **Exact `Host` matches for the legacy hosts:** `Host()` forgives a trailing dot that the backend refuses, and a `{envId}-…` label the backend redirects would reach it through the unauthenticated catch-all and name the App in its `Location`.
- **One session cookie for every app host:** it would share the cookie with every App's code on the apps domain.
- **A separate registrable domain on the Public Suffix List for Apps (e.g. `*.opsima.app`):** it would keep every App's cookies away from the platform's and from other Apps', but it costs a domain, DNS, a wildcard certificate, Keycloak redirect allowlists, standalone configuration and a Public Suffix List submission. The platform's sign-in cookie is kept from App code instead by the app proxy stripping it, and Apps on the shared registrable domain can still set cookies the others receive.
- **Existing Apps opt in through Edit URL:** every App that went live before App Slugs would keep handing out an unreadable address until its owner acted. None of the generated Apps checked reads `APP_PUBLIC_URL` or registers its own address, and the legacy hosts keep serving, so switching them breaks no link already handed out.
- **An eight-character App Short ID:** four characters shorter, but at 32 bits collisions start within tens of thousands of environments and a scan of the apps domain finds live Apps.

## Consequences

- A label that starts with a 36-character uuid takes the legacy path when that environment exists, so environment ids stay uuids and no App Slug may start with one.
- Callers cannot build the host from id and Environment Slug, so the platform and the Public API return a read-only `publicUrl` per environment. It is `null` before go-live and for a Project that serves an External Service.
- The Go proxy learns the environment id only from the backend's answer, so App Auth's forwarded-token proof is checked after the ensure call, against that id.
- A manual App Auth owner registers the `/oidc/callback` of every host the Auth dialog lists. Managed mode needs nothing: the shared identity-provider client trusts any app subdomain.
- An App switched at the upgrade hands out an address its owner never chose, and visitors of a managed App Auth App sign in again on it, since each host carries its own session cookie. An App created by an older replica during the rollout gets its App Slug at the next start.
- After an Edit URL, `APP_PUBLIC_URL` in a running pod is out of date until the pod restarts; the old readable host redirects, which browsers follow and webhook senders and most API clients don't, so those must be pointed at the new address.
- An App can carry an App Slug that no longer matches its name after a rename, until someone uses Edit URL.
- An admin can pick a regrettable Environment Slug and keep it forever, as with a repository name; the create dialog previews the resulting URL.
- Changing the agent's share-link instruction bumps the agent image and the version of every Agent that carries the platform skill.
- The wildcard DNS entry and certificate for `*.apps…` already match readable labels. The catch-all apps route and the preview route are anchored (`^…$`) and the catch-all sits at priority 1, so a suffixed or extra-label host (`{envId}-dev.apps….evil.test`, `{envId}-dev.x.apps…`) matches no route rather than slipping past an App's sign-in, and no apps hostname is long enough to lift the catch-all above the auth rules.
- A protected App answers only through its own gate route. When that route is missing or stale, its visitors get a 403 rather than an unauthenticated App until the start-up rewrite repairs it, and a duplicated or published environment whose route was never written stays unreachable. A route added outside the catch-all, such as a future custom domain, is not covered by the marker.
- The marker is enforced only where backend, proxies and chart are all new: an older proxy ignores `protected`, an older backend never sends it, and a new proxy sees no marker until the chart rolls. A request through a correct gate route never carries the marker, so they can roll out in any order.
