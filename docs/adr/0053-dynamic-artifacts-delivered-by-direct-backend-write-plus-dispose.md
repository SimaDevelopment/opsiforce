# Dynamic artifacts reach pods by direct backend write to the workspace plus dispose

Store-authored artifacts — attached Skills and Custom Agent definitions ([ADR-0051](0051-skill-catalog-append-only-store-tables.md), [ADR-0052](0052-custom-agent-anatomy-and-model-presets.md)) — are Postgres rows, but opencode discovers agents and skills exclusively as files on disk, and at the pinned version (1.18.18) it has no file watcher: the only refresh recipe is *write files, then `POST /instance/dispose`* (cheap per-directory cache flush; sessions survive; the next message sees the new state). Something must therefore turn rows into workspace files, initially and on every change. The backend already mounts the entire workspace storage (`STORAGE_MOUNT_PATH`, the same CephFS/hostPath volume agent pods mount per-project via `subPath`) and already writes workspace files through it (env-vars, webhook ingest) — and CephFS's MDS capability protocol gives strong cross-client cache coherence, so a completed backend write is visible to the pod's next read with no staleness window (validated against Ceph documentation in `.scratch/agent-skill-platform/research/delivery-flow-validation.md`, which surveyed twelve delivery patterns and found none that beats this one under our constraints).

**The backend writes dynamic files directly into the workspace over its storage mount, then disposes the pod's opencode instance when one is running. No K8s Jobs, no in-pod delivery daemon, no polling, no watchers.** Concretely:

- **One directory, one writer.** The image (init container and Agent-Updates migrate Job, both via `agent-workspace-migrate --sync-agent-files`) owns `/workspace/.opencode/skills/` (wipe-and-relay), the base `agent.md`, and `opencode.json`. The backend owns `/workspace/.opsiforce/skills/<skill-name>/` (flat, name = directory, wipe-and-relay) — declared once, statically, via `config.skills.paths` in the image's `opencode.json`, because opencode does not auto-discover directories outside its fixed conventions and the auto-discovered one is exactly the one the image wipes. In `.opencode/agents/`, where opencode's fixed discovery forces cohabitation, ownership is per file: the image owns exactly the base `<AGENT_NAME>.md`; the backend owns every other `*.md` and deletes those absent from desired state.
- **Universal sync invariant.** One idempotent sync job is the sole backend writer: it recomputes desired state from the DB, wipes-and-relays the backend-owned paths (including the Custom Agent config overlay the image's wholesale config copy clobbers), stamps a content hash (skip write *and* dispose when unchanged), and disposes a running pod. It fires on every pod start, every pool claim, every store mutation (attach, detach, pin change, new published version of an attached skill, Custom Agent profile publish, Model Preset change — debounced ~10s per project), every recovery retry, and on completion of every Agent-Updates Job. Any event that may have changed desired or on-disk state is followed by the same recompute; this reconcile discipline, not durability ceremony, is also the compensation for CephFS async-dirop loss on writer crash.
- **Delta from the built-in manifest, not the live directory.** Delivered set = the tenant's attachments for the workspace's agent minus that agent's built-in skills. Built-in membership comes from a build-time manifest (per agent, per template version — compose-skills already computes the set) reconciled into the DB and matched against the version in the workspace ledger; the live `.opencode/skills/` listing is only a defensive double-check, because that directory is legally empty mid-wipe and a delta computed from it can deliver a duplicate skill name, which opencode resolves nondeterministically.
- **Collisions: built-in wins, by omission.** Publish-time uniqueness (ADR-0051) reserves baked and global names, but a *later* platform release can ship a built-in skill with a name a tenant already published (tenant names in standalone installs are unknowable at platform-authoring time). Delivery then simply never writes the tenant's copy for that agent (delta rule above) and logs the skip — deterministic everywhere, zero extra machinery.
- **Claim-time specialization rides the same queue.** Claiming a warm pool pod enqueues a zero-delay sync (skill delta + Custom Agent prompt + Model Preset overlay, preset key falling back to the base agent's preset when absent from the running distribution) and awaits it inside the claiming window before `finalizeClaim` — verified to fit the 30s stale-claim budget (a few file writes plus one HTTP call). Failure aborts and reverts the claim; a user never receives a half-specialized pod. Routing through the queue rather than writing inline is deliberate: two unserialized wipe-and-relay writers can interleave into a corrupt tree under a valid hash stamp, which the hash-skip would then preserve.
- **Concurrency and atomicity hardening** (from the delivery-flow validation research): the per-project debounce uses BullMQ `deduplication: {keepLastIfActive: true}` — a plain stable jobId silently drops enqueues that land while a job is active, losing the mutation until an unrelated trigger; every delivered file is written temp-then-rename (the `writeJsonAtomic` house pattern — opencode reads SKILL.md bodies eagerly at rebuild, and rebuilds are triggered by actors the sync doesn't control); the hash stamp is written after the tree, so a crash yields a redundant re-sync, never a skipped one.
- **Failure posture.** Pod restart with anything unreachable: fail open — the volume persists, so yesterday's delivered files serve until the start-time sync lands (retrying on the existing 5/15/30/60-min reload ladder). Claim: fail closed (revert). No pod is ever restarted by this pipeline; dispose is the strongest action it takes, and the existing busy-session deferral applies.
- **Scope.** Delivery targets default environments only, mirroring the Agent-Updates sweep; published environments stay snapshots of publish time.

## Considered options

- **Short-lived K8s Job writer (the Agent-Updates pattern)** — rejected for this path: seconds of scheduling latency per update and per claim for what is a few file writes; the Job pattern remains where it is needed (migrations that execute inside the workspace with image binaries).
- **In-pod write endpoint on `agent-control` (orchestrator's sidecar pattern)** — rejected: simulates over an authenticated HTTP hop what the backend's existing mount does natively; adds a Go surface, a bundle endpoint, and a pod-health dependency for zero semantic gain.
- **Init-container fetch from the backend API at pod start** — rejected as redundant once the writer is the backend: the volume outlives the pod, so start-time state is whatever the backend last wrote, and the start-time sync job re-converges it without the pod ever calling home (no fetch auth, no fail-open marker protocol).
- **Serving skills from the DB at use time / `skills.urls`** — rejected: puts the store on the request path, adds a per-rebuild network dependency, and opencode's file discovery makes files mandatory anyway (research: cloudflare-openwork.md, opencode-runtime-semantics.md).
- **Restart-shaped propagation (kubeopencode) and poll-based sync (ConfigMap kubelet, openwork desktop loop)** — rejected: restarts kill 1:1 project sessions; polling trades bounded staleness for per-pod pollers with no user-controllable upper bound.

## Consequences

- Built-in file delivery is untouched — no change to `agent-workspace-migrate`, the init container, or the Agent-Updates Job beyond chaining a (hash-skipped) sync on Job completion.
- The backend gains one queue job type, one writer module, and the reconciler gains the built-in-manifest upsert; the pod image gains nothing.
- The `skills.paths` line and the `.opsiforce/skills` ownership rule must survive any future opencode upgrade review (re-verify the no-watcher and merge-order assumptions on version bumps, per opencode-runtime-semantics.md).
- The workspace root must never be deleted and recreated while bind-mounted (subPath pins the inode; the pod would see a frozen tree) — subdirectory wipes only.
- Deferred, recorded here so they aren't re-litigated: whole-tree symlink-swap atomicity for `.opsiforce/skills` (kubelet AtomicWriter pattern — collapses the stamp-last rule into the swap), Ceph `MDS_CLIENT_RECALL` monitoring as sync volume grows, per-project locks if the backend ever runs more than one replica, and store-UI surfacing of collision skips.
