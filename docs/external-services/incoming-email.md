# Incoming Email

> How does a ProjectEnvironment get a receiving email address, and what happens when mail arrives at it?

## How it works

- Incoming email is a [Built-in External Service](../../GLOSSARY.md) written on the SDK: the folder `external-services/incoming-email/` holds its `service.json`, `handlers.ts` wiring only `inbound` (it has no [Operations](../../GLOSSARY.md)) from `src/inbound.ts`, its Service skill `SKILL.md` and `test/inbound.test.ts` ([Service manifest](service-manifest.md)). The address is generated by the Project form, so it has no save hook. Sending mail is a different feature.
- Its [Service configuration](../../GLOSSARY.md), set by the platform operator on its page under Store, External Services, is the Mailgun receiving domain (`receivingDomain`), the account's webhook signing key (`signingKey`, sealed) and the largest attachment kept (`maxAttachmentMb`, default and cap 25). With the domain and key filled it is Available; without them it shows "Needs setup", Organizations do not see it, describe and the Gate answer `503 service-not-configured`, and so does its webhook.
- Upgrading a deployment needs no operator step: at boot, when `MAILGUN_RECEIVE_DOMAIN` (falling back to `MAILGUN_DOMAIN`) and `MAILGUN_WEBHOOK_SIGNING_KEY` are both set and no Service configuration is stored yet, the backend writes one from them; a stored one is never overwritten. The variables and this importer go a release later.
- A [ProjectEnvironment](../../GLOSSARY.md)'s address is its [Project configuration](../../GLOSSARY.md): `localPart`, 16 random characters from `a-z0-9`, unique across the deployment, and the rendered `address` = `<localPart>@<receivingDomain>`, shown with Copy in the chat bar's dialog and in describe's `info`. A blank `localPart` renders the address blank.
- The address exists from the first save with receiving `email.received` switched on and changes only by a confirmed Rotate in that dialog; turning receiving off keeps it but stops delivery. [Development](../../GLOSSARY.md) and each published environment have their own address: a [Publish](../projects/publish.md) never copies one, and the target keeps its own or gets a fresh one.
- Mailgun holds the receiving domain's MX records and one catch-all Route forwarding every recipient to `<OPSIFORCE_PUBLIC_URL>/api/external-services/webhooks/incoming-email` as a parsed multipart POST, attachments as file parts; the platform never parses MIME.
- The handler checks Mailgun's HMAC-SHA256 over `timestamp + token` against the signing key in constant time and refuses a signature older or newer than 300 s (`401 invalid-signature`). It turns the forward into one `email.received` Event per recipient: `address` (the local part, bound to `localPart`), `recipient`, the envelope sender as `from`, `fromHeader`, `subject`, `text` (Mailgun's stripped text, else the plain body), both bodies, `messageId`, `headers` and `attachments`, with each attachment as an Event file and the ones over `maxAttachmentMb` listed in `omittedAttachments` instead. The Event key is the `Message-Id`, falling back to the signature token, so a redelivered email is stored once.
- Routing is the generic Event rule: the email reaches the environment whose `localPart` equals the recipient's local part and whose `email.received` receiving is on. The recipient's domain is not checked, so an address issued on an earlier domain keeps receiving while Mailgun still forwards that domain.
- The Agent learns the service from its Service skill `service-incoming-email`, which a ProjectEnvironment receives once the service is enabled in its chat bar, or when its Agent carries it. The App reads the Event from `events` and `event_files` and is rung with `eventIds` ([Event](events.md)).
- External Services v2 retired the v1 Built-in Skill `incoming-email`. Once, at boot, every Agent Profile pinning it, on every Environment, pins `service-incoming-email` at its current Version instead, with no [Service settings (Agent)](../../GLOSSARY.md), or just drops the old pin where the profile already carries `service-incoming-email`; a ProjectEnvironment that switched `incoming-email` off has `service-incoming-email` switched off instead. Each Agent swapped gets a Service skill fan-out, so its existing Projects receive `service-incoming-email` and lose `incoming-email`. An Agent import that pins `incoming-email` gets `service-incoming-email` with a note ([Agent copies](../agent-system/agent-copies.md)).
- An environment with a v1 address has a Project configuration holding that address's local part (even one on another domain), receiving on. An environment whose `external-services.db` already held `messages` rows is a legacy environment and also gets each email as a `messages` row with inline `attachments`, and `rowIds` in its ring.

## Edge cases

- When the signature fields are missing, wrong or stale, the webhook answers 401 and stores nothing.
- When no environment has the recipient's local part, or that environment's receiving is off, the webhook answers 200 and the inbound Call is logged `unmatched`; Mailgun does not bounce the sender.
- When the Mailgun settings do not fit the Service form (say a malformed domain), the importer logs an error and writes nothing; the operator fills the form instead.
- When a v1 address collides with one another environment already holds, both environments keep it and both receive mail sent to it.

## Code

- `external-services/incoming-email/` — the manifest, `handlers.ts`, `src/inbound.ts` (Mailgun signature, attachments, Event mapping), the Service skill and its tests (`yarn workspace @opsiforce/external-services test`).
- `backend/src/external-services/upgrade/incoming-email-upgrade.ts` — the one-release importer of the Mailgun settings.
- `backend/src/external-services/upgrade/retired-skill-swap-upgrade.ts` — the one-release swap of `whatsapp` and `incoming-email` pins for their Service skills.
- `backend/db/migrations/0076_external-services-v2.sql` — the External Services v2 schema, including the move of v1 addresses.
- `backend/src/external-services/legacy/legacy-messages.ts` — the `messages` row a legacy environment gets for each email.
