# New External Service

What this service lets Projects do with the upstream, for whoever maintains it next.

## Upstream

The upstream, the credential the Service form asks for and the permissions it was granted, the protections set on the upstream itself, and where the upstream's own audit of what this service did is kept.

## Groups

One line per group in `src/groups/`: what it lets through and the setting that governs it. Everything outside a group is *not supported*.

## Events and Usage

The Event types the service delivers and how a Project chooses what it hears; the Usage counters it keeps.

## Not in this version

The upstream's capabilities this version leaves out, one line each, as agreed at Stop 1.

## Layout

| Path | Holds |
|---|---|
| `service.json` | the manifest: name, both forms, Event types |
| `service.types.ts` | generated by `yarn types` from `service.json` |
| `service.ts` | `defineService({ manifest, routes, … })`, the groups' routes in order |
| `src/upstreams.ts` | the only file that knows the upstream's address and credentials |
| `src/groups/<group>.ts` | one group per file, each exporting `routes` |
| `src/access.ts` | the helper every group's check calls to read the settings |
| `src/forms.ts`, `src/hooks.ts`, `src/inbound.ts` | form handlers, save hooks and the webhook handler, when the service has them |
| `test/groups/<group>.test.ts` | each group through `testService(service, …).fetch` |
| `test/service.test.ts` | a request outside every group is *not supported* |
| `SKILL.md` | the Service skill every consuming Agent reads |
| `PUBLISH.md` | the Publish note for the next Publish: what changed and what each group lets through |
